# The MOI Docs GEO Standard

Practical rules for writing MOI documentation that search engines and AI answer engines (ChatGPT, Perplexity, Claude, Google AI Overviews) can find, parse, and cite correctly. Applies to docs.moi.technology, voyage-docs.moi.technology, docs.wallet.moi.technology, cocolang.dev, js-moi-sdk.docs.moi.technology, and moi.technology.

If a rule here conflicts with a framework default, the rule wins.

---

## The 10 Rules Every Page Must Pass

Before you merge any doc page, check every box.

- [ ] **1. One H1.** Exactly one, and it matches the page's actual topic.
- [ ] **2. Title has no version numbers.** `Accounts | MOI Docs`, never `Accounts v2.3 | MOI Docs`.
- [ ] **3. Title follows `Page Name | Site Name`.** Under 60 characters total.
- [ ] **4. Description is hand-written, 140–160 characters, answer-shaped.** Not the Docusaurus placeholder. Not auto-truncated from the first paragraph.
- [ ] **5. First paragraph answers the page's implicit question in plain language** before any setup, history, or "in this guide we'll cover." This is the citable paragraph — assume an AI engine will quote only this.
- [ ] **6. Entity names match the canonical spelling table** (below) everywhere on the page: title, headings, body, alt text, schema.
- [ ] **7. `url` in the site config points at the real production domain**, and canonical/sitemap URLs resolve to a live 200, not a redirect or 404.
- [ ] **8. No template scaffolding shipped**: no `facebook/docusaurus` editUrl, no sample blog posts, no "Lorem ipsum" or placeholder description, no unedited `docusaurus.config.js` favicon/logo.
- [ ] **9. Stub or unfinished pages are `noindex`** and excluded from the sitemap until content is real.
- [ ] **10. `curl -A "GPTBot/1.0" <url>` returns 200**, not a Cloudflare challenge or block.

## Page Metadata Rules

| Element | Rule |
|---|---|
| **Title** | `<Page Name> \| <Site Name>`. 50–60 characters. No version numbers, no build IDs, no dates unless the page is explicitly a changelog entry. |
| **Description** | 140–160 characters. Hand-written per page — never the Docusaurus default (`"My site description"` or similar) and never auto-generated by truncating body text. Write it as a direct answer to what the page covers, not a teaser. |
| **Description + colons (YAML)** | Frontmatter is YAML. A description containing a colon followed by a space (`Accounts: the basic unit`) breaks the parser unless quoted. Always wrap descriptions containing a colon in quotes: `description: "Accounts: the basic unit of state in MOI"`. |
| **H1** | Exactly one per page. It should read like a title, not a sentence with a period. |
| **H2s** | Where the section answers a reader's question, phrase the H2 as that question: `## How do I create an account?` beats `## Account Creation`. AI answer engines lift question-phrased headings directly into "People also ask" and chat answers. Don't force every H2 into a question — only where the content genuinely answers one. |

## Answer-First Writing Pattern

The first paragraph under the H1 is the **citable paragraph**. Assume it is the only text an AI engine will quote verbatim. It must:

1. Define or answer the page's core question in one or two plain sentences.
2. Contain no throat-clearing ("In this guide, we will explore…", "Before we begin…").
3. Stand alone — readable and correct with zero prior context.

Setup, prerequisites, and background go **after** the citable paragraph, not before it.

### Example 1 — Accounts page

**GOOD (ship this pattern):**
> Every distributed network needs a standard way to represent the entities that participate in it. In MOI, this is the account — a unit of state that holds balances, ownership, and interaction history for a single participant.

Answers "what is an account" in the first sentence. Self-contained. Quotable as-is.

**BAD (what it replaces):**
> Before diving into accounts, it's worth understanding a bit about how MOI structures its network. This section will walk you through the account model step by step, starting with some background on distributed ledgers in general.

No definition anywhere in the paragraph. An AI engine has nothing to cite — it has to keep reading, and most won't.

### Example 2 — MOI Wallet connect page

**GOOD:**
> MOI Wallet is the reference wallet for the MOI protocol. Connecting it to a dApp grants that dApp read access to your account address and the ability to request interaction signatures — it never exposes your private key.

Defines the product, states the security boundary, answerable as a standalone quote.

**BAD:**
> Wallets are an essential part of any blockchain ecosystem, and MOI is no exception. In this section we'll cover everything you need to know to get your wallet connected and ready to go.

Generic, no product definition, no fact an engine could extract.

## Entity Naming Table

Use these spellings everywhere — titles, headings, body copy, alt text, JSON-LD `name` fields. Do not vary by page or author.

| Entity | Canonical spelling | Never write | Notes |
|---|---|---|---|
| Protocol | **MOI** | Moi, moi (mid-sentence) | Tagline: "The participant layer for AI agents." Use the tagline verbatim in meta descriptions and `Organization.description` schema where space allows. |
| Wallet | **MOI Wallet** | Moi Wallet, MoiWallet, moi wallet | Capital M-O-I, capital W. |
| Language | **Coco** | CocoLang | On first mention per page, write "Coco (also known as Cocolang)". After first mention, "Coco" alone is fine. Never "CocoLang" — that capitalization does not exist in any canonical source. |
| SDK | **js-moi-sdk** | JS-MOI-SDK, Js-Moi-Sdk | Always lowercase, including at the start of a sentence — rephrase the sentence instead of capitalizing it. |
| Explorer / developer gateway | **Voyage** | voyage (mid-sentence, when referring to the product name) | The MOI network explorer and developer gateway. Standard proper-noun capitalization. |
| Company | **Sarva Labs** | Sarva Labs Inc, SarvaLabs | Use in footer/legal and `Organization` schema `name` where the entity is the company rather than the protocol. |

**Rule:** the spelling used in a page's title, H1, and body must be identical to the spelling used in that page's JSON-LD. A schema `name` that disagrees with the visible heading is a mismatch signal to AI crawlers.

## New-Page Checklist

Run this for every new doc page before merging:

- [ ] Frontmatter has `title` and `description` set explicitly (not inherited/default).
- [ ] Description is quoted if it contains a colon.
- [ ] Exactly one H1; it is the frontmatter `title` or a close variant.
- [ ] Question-phrased H2s used where content answers a question.
- [ ] First paragraph is the citable paragraph — plain-language answer, no throat-clearing.
- [ ] Entity names match the canonical table.
- [ ] No leftover "Coming Soon," "TBD," or "Lorem ipsum" content — if the page is a real stub, it is `noindex`.
- [ ] Internal links use root-relative paths that match the site's `trailingSlash` config (no `/page` vs `/page/` mismatches).
- [ ] Page added to the site's sidebar/nav config, not orphaned.

## New-Site Checklist

Run this once when standing up or migrating a documentation property:

- [ ] `url` (Docusaurus) or equivalent base URL config points at the real production domain — not a staging domain, not a placeholder, not a dead domain. This single field poisons every canonical tag and the sitemap if wrong.
- [ ] All template scaffolding removed: sample blog posts, `facebook/docusaurus` editUrl, default favicon/logo, placeholder tagline/description in the site config.
- [ ] `robots.txt` present at the domain root, explicitly allowing standard crawlers and known AI crawlers (GPTBot, ClaudeBot, PerplexityBot, Google-Extended) unless there is a deliberate reason to block one.
- [ ] `llms.txt` present at the domain root (see Maintenance Rules — this is generated, not hand-written).
- [ ] JSON-LD emitted on every page at minimum: a `WebSite`/`TechArticle` node for the page, plus a `publisher` node referencing the shared organization identity `https://moi.technology/#organization` by `@id` (don't redefine the Organization inline on every page — reference it).
- [ ] `sitemap.xml` generated, submitted to Search Console, and spot-checked for stub/draft pages that shouldn't be there.
- [ ] `og:image` / social card configured (`themeConfig.image` in Docusaurus) — a real branded image, not the framework default.
- [ ] Verify end-to-end: `curl -A "GPTBot/1.0" -I https://<domain>/` returns `200`, not a Cloudflare challenge page.

## Maintenance Rules

- **`llms.txt` is generated, not hand-edited.** When pages are added or removed, regenerate it from the source of truth (sidebar/nav config or a build script). Hand-editing causes drift the moment the next page ships.
- **Stubs are `noindex` until real.** A "Coming Soon" page is a stub. It does not go in the sitemap, and it carries `<meta name="robots" content="noindex">` (or the Docusaurus/Sphinx equivalent) until it has real content — then both are removed in the same PR that adds the content.
- **Sitemaps get reviewed, not assumed.** After any content restructure, generate and read the sitemap. A stub or sample page appearing there unnoticed is the single most common failure across this estate — check for it explicitly.
- **Re-verify crawler access after any Cloudflare or hosting change.** Any change to a WAF rule, bot-fight mode, firewall rule, or hosting provider can silently start blocking AI crawlers. Run `curl -A "GPTBot/1.0" -I <url>` (swap in `ClaudeBot`, `PerplexityBot`, `Google-Extended` too) and confirm `200` after every such change, not just at launch.

## Framework Quick Reference

| What | Docusaurus (2.1 / 3.x) | Sphinx / RTD | Plain React SPA |
|---|---|---|---|
| Site base URL | `url` in `docusaurus.config.js` | `html_baseurl` in `conf.py` | Set in hosting config / meta tags in `index.html` |
| Trailing slash behavior | `trailingSlash` in `docusaurus.config.js` — set explicitly, don't rely on the default | Controlled by web server config, not Sphinx itself | Controlled by hosting/router config |
| Social card / og:image | `themeConfig.image` in `docusaurus.config.js` | `.. meta::` directive per page, or a sitewide default in `_templates/layout.html` | `<meta property="og:image">` in `index.html` `<head>` (static — SPA head tags don't update per-route without SSR/prerendering) |
| Static assets (robots.txt, llms.txt, favicons) | `static/` directory | `html_extra_path` in `conf.py` | `public/` directory |
| Per-page description | Frontmatter `description:` field | `.. meta::` directive at top of the `.rst`/`.md` file | Per-route `<meta>` injection (requires react-helmet or SSR — a client-only SPA cannot vary head tags per route for crawlers that don't execute JS) |
| Custom head injection (JSON-LD, extra meta) | `headTags` in `docusaurus.config.js`, or a swizzled `Layout` component | `_templates/layout.html` block overrides | `index.html` `<head>`, or injected via `react-helmet` (note: JS-only injection is invisible to crawlers that don't execute JavaScript — prerender or SSR if this matters) |
| JS-only content visibility | Generally fine — Docusaurus prerenders to static HTML at build time | Fine — Sphinx output is static HTML | **Risk.** A client-rendered SPA is invisible to crawlers that don't execute JS. Prerender, use SSG, or serve a static snapshot for bot user agents. |

## PR Review Checklist for Docs Reviewers

Before approving any docs PR:

- [ ] Title and description are hand-written, correct length, no version numbers in the title.
- [ ] Exactly one H1; H2s are question-phrased where the content is answering a question.
- [ ] First paragraph is a standalone, plain-language answer — not a lead-in.
- [ ] Entity names match the canonical table exactly (MOI, MOI Wallet, Coco, js-moi-sdk, Voyage, Sarva Labs).
- [ ] No stub/placeholder content shipped un-flagged (`noindex` set if it's not finished).
- [ ] No new template scaffolding reintroduced (check `docusaurus.config.js` diffs for editUrl, image, or tagline changes).
- [ ] If this PR touches site config, hosting, or Cloudflare rules: confirm `curl -A "GPTBot/1.0"` still returns 200.
- [ ] If this PR adds/removes pages: confirm `llms.txt` was regenerated and the sitemap doesn't carry orphaned or stub URLs.
